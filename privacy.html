Privacy policy

This policy describes the Google Drive backup integration for a personal, owner-operated Digital Familiar installation.

Data accessed and its purpose

The integration requests the Google Drive drive.file permission. It accesses the contents and metadata of files and folders created by, or specifically made available to, this application. For backup operations, those contents are encrypted backup archives; relevant metadata includes file and folder names, identifiers, sizes, and timestamps.

This access is used to store backups, locate the application's backup folders and files, verify uploaded bytes, and download a backup for owner-requested recovery. The integration does not request permission to read the account's entire Drive.

The integration stores Google authorization tokens in a private configuration directory on the owner's computer so scheduled uploads can operate after the initial consent. The owner is responsible for protecting access to that computer and directory.

Backup contents and encryption

A backup can contain conversations, saved memories, other application records, configuration, credentials included in that configuration, and application recovery files. This bundle is encrypted locally with age before upload.

The private recovery key is kept by the owner separately from the uploader and is not sent to Google Drive. Google receives the encrypted archive and can observe metadata such as its filename, size, and upload time. Encryption does not conceal all metadata or protect an unlocked, compromised owner device.

Storage, sharing, and use

Local backup copies and authorization tokens are stored on the owner's equipment. Encrypted offsite copies are stored in the Google Drive account the owner authorizes. During verification or recovery, the encrypted copy is downloaded to the owner's equipment.

The backup integration does not sell Google user data, use it for advertising, or send data retrieved from Google Drive to AI services. It does not use that data to develop, improve, or train generalized or non-personalized AI or machine-learning models. Other separately configured Digital Familiar features have their own data flows; this policy covers the backup integration.

Google data is used solely to provide the owner-requested backup and recovery features, consistent with the Google API Services User Data Policy and its Limited Use requirements. Google operates its service under its own privacy policy.

Retention, deletion, and revoking access

Completed local and cloud backups are retained until the owner removes them. This version of the integration does not automatically prune old backups or remove existing cloud copies. Removing a record from the live application does not remove that record from earlier backup archives.

The owner can stop the offsite service on their computer and revoke the application's access through their Google Account's third-party connections settings. Revoking access stops future authorized API access; existing local and Drive backups require separate deletion by the owner.

To remove stored backup data, the owner can delete the relevant local copies and Google Drive backup files, and empty Drive trash when permanent deletion is intended. Google's own retention rules may apply to data within its service. Local authorization tokens can also be removed after the integration is stopped.

This information website

These static pages contain no forms, advertising, analytics scripts, or embedded third-party content. The site does not receive backup archives or authorization tokens. If hosted on GitHub Pages, GitHub records visitor IP addresses for security purposes under its privacy statement.

Contact and updates

For questions about this installation or its data practices, use the user support email listed on the application's Google authorization screen. The Google Cloud project owner maintains that address. Material changes to the integration's data practices should be reflected here before they are enabled.
